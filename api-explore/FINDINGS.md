# data.go.kr API 실측 결과 (2026-09-01)

4개 API에 실제 키를 넣어 호출해본 결과. 목적은 "이 데이터로 배점/자격 엔진(program.ts)을
채울 수 있는가" 확인.

## 1. 청약홈 분양정보 조회 서비스 (odcloud stage 37000) — ✅ 정상 동작

- `GET https://api.odcloud.kr/api/ApplyhomeInfoDetailSvc/v1/getAPTLttotPblancDetail`
- `GET .../getAPTLttotPblancMdl` (주택형별 상세)
- 인증: 쿼리파라미터 `serviceKey` (디코딩된 raw 키를 URL-encode해서 전달. **주의**: data.go.kr이
  발급하는 키는 이미 URL-encode된 상태(`%2F`, `%3D%3D` 포함)라, curl `--data-urlencode`에
  그대로 넣으면 이중 인코딩되어 401(`등록되지 않은 인증키`)이 남. 반드시 한 번 디코딩한
  raw 값을 다시 encode해야 함.)
- 실제 응답 필드: 공고명/주소/시행사/시공사/접수기간/당첨자발표일/입주예정월/공급유형코드
  (APT/오피스텔/신혼희망타운 등)/지역코드, 주택형별 공급면적·세대수·분양최고금액(만원)·
  특별공급 유형별(신혼부부/생애최초/다자녀/노부모부양 등) 세대수 breakdown.
- **없는 것**: 소득기준, 자산기준, 청약통장 요건, 배점표. 즉 "어떤 공고가 있는지"는
  주지만 "내가 자격이 되는지"는 안 줌.

## 2. 청약홈 경쟁률/당첨가점 조회 (odcloud stage 36148) — ✅ 정상 동작

- `getAPTLttotPblancCmpet` (실시간 경쟁률), `getAptLttotPblancScore` (당첨가점: 최저/평균/최고),
  그 외 특별공급 신청현황 등 8개 오퍼레이션.
- 실제 값 확인됨(예: 특정 공고 특정 주택형의 해당지역 평균가점 41.53, 최저 30, 최고 64).
- 접수 마감 전 공고는 값이 `-` 또는 `0`으로 비어있음(당연히 아직 경쟁 데이터가 없으니까).
- 이건 "과거 이 정도 지역이 보통 몇 점 커트라인이었다" 같은 참고 정보로는 쓸만하지만,
  자격 판정 자체와는 무관.

## 3. LH 분양임대공고문 조회 서비스 — ✅ 정상 동작 (경로 수정 후)

- 문서상 Base URL(`https://apis.data.go.kr/B552555/lhLeaseNoticeInfo1`)만으로는 400
  (`NO_OPENAPI_SERVICE_ERROR`)이 남. 실제 요청 경로는 오퍼레이션명이 한 번 더 붙는
  `https://apis.data.go.kr/B552555/lhLeaseNoticeInfo1/lhLeaseNoticeInfo1`.
- 파라미터도 문서 초안과 다름: `ServiceKey`, `PG_SZ`, `PAGE`, (선택)`PAN_NM`,
  `UPP_AIS_TP_CD`, `CNP_CD`, `PAN_SS`.
- 응답: 공고ID/공고명/공고유형/지역/공고일/접수마감일/공고상태 + LH 자체 상세페이지
  링크(`DTL_URL`)뿐. 상세 조건은 결국 그 링크(공고문 PDF/HTML)를 또 봐야 함 — 이 API도
  "목록 인덱스" 그 이상이 아님.

## 4. LH 공공임대주택 단지정보 조회 (`data.myhome.go.kr`) — ❌ 이 샌드박스에서 접근 불가

- TLS handshake 자체가 10초 타임아웃 (프록시 CONNECT는 성공하지만 그 다음 TLS
  ClientHello 이후로 응답이 없음). 인증키/파라미터 문제가 아니라 이 도메인 자체가
  이 네트워크 환경에서 막혀있는 것으로 보임 (이전에 `soco.seoul.go.kr`에서 겪은 것과
  같은 패턴).
- 필요 파라미터는 확인해둠: `ServiceKey`(필수), `brtcCode`/`signguCode`(필수, 광역시도/
  시군구 코드), `numOfRows`/`pageNo`(선택). 응답 필드에는 단지명/주소/자치구/임대유형/
  전용면적/보증금(`bassRentGtn`)/월임대료(`bassMtRntchrg`) 등이 있다고 문서에 나옴 —
  이게 사실이면 자치구별 단지 매핑에는 쓸모 있을 수 있음. **확인 필요**: 사용자가
  본인 브라우저에서 직접 호출해서 응답을 붙여넣어주면 실물 확인 가능.

## 결정적 발견: SH 장기전세주택은 이 생태계 자체에 없음

`getPblPvtRentLttotPblancDetail`(공공지원 민간임대)에서 `HOUSE_NM LIKE '장기전세'`로
검색 → **0건** (전체 183건 중 매칭 없음). 청약홈 API가 다루는 상품군(APT 분양/오피스텔/
공공지원민간임대/무순위·잔여세대/임의공급)에 SH의 "장기전세주택"은 애초에 포함되지 않음.
SH 장기전세는 청약홈이 아니라 **SH공사 자체 인터넷청약시스템**에서만 공고·접수되는
상품이라, data.go.kr 생태계 전체가 이 상품 자체를 모른다.

## 결론 (LLM 필요 여부에 대한 실측 근거)

4개 API 전부 합쳐도 얻을 수 있는 건 "공고가 어디 있고 언제 접수하고 경쟁률이 얼마였는지"
뿐이고, **소득기준표/자산기준/청약통장 요건/배점표 — 즉 program.ts 스키마가 필요로 하는
핵심 자격 데이터는 어느 API에도 없음**. 이건 desk research 단계 결론과 정확히 일치하고,
이제 실제 호출로 확인됐다는 점이 다름.

→ MOD-01(공고문 PDF → 구조화 추출)은 이 4개 API로 대체 불가. 이 API들은 오히려
"보조 기능"(공고 자동 수집/최신 공고 알림, 실시간 경쟁률·과거 커트라인 표시,
주소→자치구 매핑)에 쓰는 게 맞고, 핵심 자격 룰은 여전히 사람이 검증하거나
LLM으로 추출해야 함.
